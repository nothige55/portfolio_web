# 통합 DnD 데모 설계 (방향)

이 문서는 홈 첫 데모(Trego 드래그)를 "DnD 전체 시스템의 발전 과정과 통찰"로 다시 만드는 방향을 정한다. 세부 구현과 시각 다듬기는 방향 승인 뒤 별도 작업으로 한다. 홈 전체 디자인은 `2026-11-11-home-design-surgiauth-demo-design.md`를 따른다.

## 의도

Trego의 드래그 앤 드롭은 약 16개월 동안 드롭 판정 모델이 10번 가까이 바뀐 작업이다. 지금 홈의 데모는 평평한 장소 4개를 세로로 재정렬할 뿐이라 이 고민 대부분이 빠져 있다. 가장 큰 빠진 부분이 계층(폴더 → 날짜 → 그룹 → 장소)이다.

방문자가 하나의 트리에서 단계를 넘기며 "같은 화면에서 판정, 피드백, 의도 구분이 어떻게 바뀌었는지"를 직접 만져 보게 한다. 출처는 `~/trego_docs/인터랙션-dnd.md`와 `인터랙션-변경-이력.md`다.

## 결정 사항 (사용자가 정함)

- 데모는 계층 이야기와 DnD 이야기를 분리하지 않고 하나로 통합한다. (별도 "계층 이동" 구간은 만들지 않는다.)
- 통합 방식은 기존 `DragStory`의 세 단계(`V1~V3`, `V4`, `V5~V6`) 위에서 변화 과정을 보여 주는 것이다.
- 자식으로 넣기(의도 구분)까지 이번 범위에 넣는다.
- 세부 구현은 나중에 한다. 데모를 실제 Trego처럼 보이게 다듬는 일도 방향이 정해진 뒤 별도 단계로 한다.
- 계층 이동의 과거 기록은 X좌표로 목표 계층을 고르는 방식(2025-07, 레거시 `44e0352`)에서 출발한다. Confluence는 UI 참고처가 아니라 QA·피드백 목록을 모아 둔 문서 도구였다. X좌표 계층 이동의 참고처로 기록에 남은 것은 Figma·Notion의 들여쓰기 드롭이다(`7b8a5da`).

## 목표, 비목표, 반목표

- 목표: 단계를 넘길 때 무엇이 바뀌었는지가 설명을 읽기 전에 화면에서 읽힌다. 세 축(판정, 피드백, 의도 구분)이 모든 단계에서 한 화면에 보인다. 방문자가 끌어서 계층 이동과 자식 넣기를 직접 해 볼 수 있다.
- 비목표: `/dnd` 페이지 변경, 실제 Trego 저장소 코드 가져오기, 날짜·폴더 드래그(장소만 끈다), 다중 선택·undo.
- 반목표: 세 축이 한꺼번에 나와 무엇을 봐야 할지 모르는 화면. 타이머와 자동 펼침이 얽혀 조작이 불안정한 데모.

## 제약

- 새 의존성을 넣지 않는다. 지금처럼 포인터 이벤트로 만든다.
- 기존 `DragStory`의 화면 고정(pin)과 스크롤 연동, 단계 버튼 `V1~V3 / V4 / V5~V6`, 모바일·움직임 줄이기 대체 동작을 유지한다.
- 드롭 규칙은 UI 밖 순수 함수로 두고 Node 내장 테스트로 고정한다. SurgiAuth의 `hand-orientation.ts`와 같은 방식이다.
- 구간 id와 경로 바는 그대로다.

## 접근 방식

| 안 | 내용 | 평가 |
|---|---|---|
| 계층 이동 구간을 별도로 만들기 | `trego-drag`와 `trego-nav` 사이에 구간 추가 | 변화 과정이 사라져 완성형만 남는다. 사용자가 거부했다. |
| **`DragStory` 데모를 트리로 통합 (선택)** | 세 단계가 모두 같은 트리에서 일어난다 | 실제 이야기(판정 모델의 반복)와 닮았고, 사용자가 원한 형태다. 비용이 가장 크다. |
| 설명만 추가 | 단계 설명에 한두 줄 | 만져 볼 수 없어 홈의 목적과 어긋난다. |

## 데모 구성

### 트리 (제 제안)

- 폴더 `제주 여행` → 날짜 `1일차`, `2일차` → 그룹 하나와 장소들.
- 1일차: `공항`, 그룹 `해안 코스`(`이호테우`, `협재해수욕장`), `동문시장`. 2일차: 비어 있음.
- 그룹을 넣는 이유: 장소는 날짜 또는 그룹 아래에만 놓을 수 있어서, 그룹 마지막 장소 뒤에서 "몇 단계 위로 빠져나갈지"를 X좌표로 고르는 계층 이동이 성립한다. 그룹이 없으면 허용 계층이 하나뿐이다.
- 끌 수 있는 것은 장소뿐이다. 이름과 구성은 빌더가 다듬어도 된다.
- 지도는 지금처럼 옆에 두고, 트리에서 장소 순서를 뽑아 넘긴다.

### 놓을 수 있는 곳의 규칙

- 장소는 날짜 또는 그룹의 자식이다. 폴더 바로 아래와 장소 아래에는 놓을 수 없다.
- 계층 후보는 "이웃 행의 조상 중 위 규칙을 만족하는 것"이다.

### 단계별 변화

| 단계 | 판정 | 피드백 | 의도 구분(자식으로 넣기) |
|---|---|---|---|
| V1~V3 | 행 위·가운데·아래 세로 구역에 더해, 포인터의 가로 위치를 들여쓰기 칸수로 환산한다. 놓을 수 없는 깊이도 그대로 계산된다. | 깊이만큼 들여쓴 삽입선. 가운데 구역은 파란 외곽선 | 행 가운데 구역에 놓으면 자식 |
| V4 | 놓을 수 있는 계층 목록을 만들고, 가로 위치를 가장 가까운 허용 계층에 붙인다. | 놓일 자리에 반투명 미리보기가 붙고 형제가 벌어져 자리를 연다. 놓을 수 없는 곳에서는 사라진다. | 컨테이너 위에서 머무르면 자식 |
| V5~V6 | 같음 | 지도와 경로가 함께 반응한다(데모용 좌표) | 채움이 다 차는 1초 뒤에 허용한다. 자동 펼침 직후에는 7.5px 더 움직이기 전까지 판정을 미룬다. |

- 모든 단계에서 세 축이 보이되, 이전 단계에서 바뀐 부분을 화면에서 짚어 준다(예: 바뀐 축에 작은 표시). 표시 방식은 빌더가 정한다.
- 단계 설명과 `chapters.ts`는 위 표의 내용을 반영해 고친다. 기록에 근거한 것만 쓴다.

## 만드는 순서 (제 제안)

1. 드롭 규칙 순수 함수와 테스트, 트리 렌더링, V1~V3 판정과 삽입선.
2. V4 허용 계층 스냅과 미리보기.
3. 머무름 자식 드롭, 채움, 7.5px 데드존, 지도 연동.
4. 실제 Trego처럼 다듬기(재설계본 `trego-web-portfolio`의 행 높이, 들여쓰기, 선택·hover 색, 경로 정보 줄). 별도 단계다.

## 빌더에게 남기는 것

- 트리의 정확한 이름과 개수, 행 크기, 단계별 "바뀐 곳" 표시 방식.
- 머무름과 채움 타이밍의 실제 값(기록상 500ms, 1000ms, 채움 1초 + 확정 0.8초, #20에서 1초로 정리된 값을 참고).
- 순수 규칙 모듈의 시그니처와 테스트 경계값.
- 좁은 화면에서 트리와 지도를 어떻게 쌓을지.

## 사용자가 정해야 하는 것

- 트리 구성(그룹 이름과 장소 배치)이 맞는지.
- 단계별 설명 문구 최종본.
- 실제 Trego처럼 다듬는 단계의 시작 시점.
