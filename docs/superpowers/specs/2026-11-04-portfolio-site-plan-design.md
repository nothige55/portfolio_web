# 포트폴리오 사이트 구성 계획

## 의도

프론트엔드 채용 담당자와 면접관에게, "드래그 하나를 세 번 다시 만든 과정"으로 인터랙션 판단력을 보여 주는 사이트다. 기능 오류 수정이 아니라 **사용자가 느끼는 UX가 어떻게 바뀌었는가**가 중심이다. 이 문서는 사이트 구성만 다룬다. DnD 체험 컴포넌트는 이번 범위에서 비워 두고 자리만 만든다.

## 결정 사항 (사용자가 정함)

- 대상: 프론트엔드 채용.
- 구조: 멀티 페이지.
- 분위기: 미니멀 에디토리얼.
- 언어: 한국어만.
- 다른 프로젝트: 나중에 정한다. 이번에는 목록을 만들지 않는다.
- 소개 내용: 구조만 만들고 문구는 나중에 사용자가 채운다.
- 배포: Vercel 기본 도메인.
- 연락처: 이메일, GitHub.

## 목표와 비목표

- 목표: 첫 화면이 가볍고, 3덩어리 변화(A/B/C)가 한눈에 읽히며, 채용 담당자가 30초 안에 "무엇을 하는 사람인지"와 연락 방법을 알 수 있다.
- 비목표: 블로그, 다국어, 백엔드, 분석 도구, 프로젝트 목록(이번에는 제외).
- 반목표(기술적으로 동작해도 실패인 경우): DnD 데모 3개가 한 화면에 몰려 첫 화면이 무거워지는 것. 설명 없이 데모만 있어서 "왜 바뀌었는지"가 안 읽히는 것.

## 페이지 구성

| 경로 | 역할 | 내용 |
|---|---|---|
| `/` | 요약과 입구 | 한 줄 소개, A/B/C 변화 티저 카드 3개(각각 `/dnd`의 해당 챕터로 링크), 소개 페이지 링크 |
| `/dnd` | 핵심 케이스 스터디 | 과제 정의, 챕터 A/B/C. 각 챕터는 `체험 자리(비어 있음)`, `사용자가 느낀 것 한 줄`, `바뀐 이유`, `커밋 링크` |
| `/about` | 소개 | 관심사, 이력, 스택(자리표시 문구), 연락처(이메일, GitHub) |

- 공통: 상단 헤더(홈, DnD, 소개)와 하단 푸터(이메일, GitHub).
- `/dnd` 챕터 A/B/C의 체험 자리는 "준비 중" 표시가 있는 빈 박스다. 나중에 `features/dnd/v3`~`v6`의 데모를 이 자리에 꽂는다.
- 모바일: 데모는 마우스 기준이라 체험 자리에 "데스크톱에서 보세요" 안내를 둔다.

## 시각 방향 (제 제안, 확정 아님)

- 읽는 폭은 좁게(약 680px) 두고, 데모 자리만 넓게(약 1100px) 쓴다. 여백과 타이포가 주인공이다.
- 제목은 세리프, 본문은 산세리프. 한글은 Noto Serif KR과 Pretendard 조합을 제안한다.
- 색은 무채색 위주에 포인트 색 하나. 포인트는 DnD 고스트의 파란색을 재사용한다.
- 다크 모드는 시스템 설정을 따른다.
- shadcn 컴포넌트를 우선 쓴다: `button`, `card`, `tabs`, `badge`, `separator`.

## 코드 배치 (bulletproof-react)

- `src/app/`: `layout.tsx`(헤더, 푸터, 폰트, 메타데이터), `page.tsx`, `dnd/page.tsx`, `about/page.tsx`. 페이지에서 features를 조합한다.
- `src/components/layouts/`: 헤더, 푸터.
- `src/config/site.ts`: 사이트 이름, 이메일, GitHub 주소, 자리표시 문구.
- `src/features/dnd/components/`: 챕터 레이아웃과 체험 자리(빈 박스) 컴포넌트.
- `src/features/profile/components/`: 홈 한 줄 소개, 소개 페이지 섹션.

## 접근 방식

고려한 방식은 둘이다.

1. **페이지를 먼저 만들고 내용은 자리표시로 채운다 (선택).** 구조와 시각 톤을 먼저 확정할 수 있고, 문구는 나중에 `site.ts`와 각 섹션에서 바꾸면 된다.
2. 문구를 먼저 받고 완성형으로 만든다. 사용자가 내용을 아직 채우지 않기로 했으므로 맞지 않는다.

## 만드는 순서

1. 레이아웃 뼈대: 폰트, 색 토큰, 헤더, 푸터, 메타데이터.
2. 홈: 한 줄 소개와 A/B/C 티저 카드.
3. `/dnd`: 과제 정의와 챕터 3개(체험 자리는 빈 박스).
4. `/about`: 관심사, 이력, 스택, 연락처(자리표시).
5. Vercel 연결과 배포.
6. 이후(별도 작업): DnD 체험 컴포넌트 V3~V6, 다른 프로젝트 소개.

## 빌더에게 남기는 것

- 헤더와 카드의 세부 간격, 폰트 크기 같은 시각 값은 위 방향 안에서 정한다.
- 자리표시 문구의 말투는 담백한 해요체로 둔다(사용자가 나중에 교체).

## 사용자가 정해야 하는 것

- 사이트에 표시할 이름과 한 줄 소개 문구.
- 이메일 주소.
- 시각 방향(세리프 제목, 포인트 파란색)에 대한 동의.
